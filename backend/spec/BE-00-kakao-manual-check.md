# BE-00 카톡 "나에게 보내기" 수동 확인

- 주차: 1주차 (11/25) · 우선순위: P0 (위험 확인) · 계획: B0
- 근거: 요구사항 10절, 기술 4.4·9절
- 선행: 없음 · 이 작업을 쓰는 작업: BE-04, BE-12

## 목적

12/25 개봉 알림이 이 서비스의 핵심이다. 코드를 짜기 전에 카카오 API만으로 "나에게 보내기"가 실제로 되는지 첫날 확인한다. 안 되면 계획의 대체안(캘린더 추가, 홈 안내)으로 바로 방향을 바꾼다.

## 확인할 것

1. 카카오 디벨로퍼스 앱 설정
   - 플랫폼 > Web 사이트 도메인: `http://localhost:5173`
   - 카카오 로그인 활성화, Redirect URI: `http://localhost:5173/oauth-test`, `http://127.0.0.1:54321/auth/v1/callback`
   - Client Secret 활성화
   - 동의항목: 닉네임, 프로필 사진, **카카오톡 메시지 전송(`talk_message`, 선택 동의)**
2. 인가 코드 → 토큰 발급 → "나에게 보내기" → refresh token으로 갱신 → 갱신한 토큰으로 다시 보내기. 명령은 1주차 계획 B0 단계를 따른다.
3. Supabase 카카오 로그인이 이메일 동의(`account_email`)를 요구하는지, 그 항목을 비즈 앱 전환 없이 켤 수 있는지.

## 완료 조건

- [ ] 발송 응답이 `{"result_code":0}`이고, 카카오톡 "나와의 채팅"에 메시지가 도착한다.
- [ ] 갱신한 access token으로도 발송에 성공한다.
- [ ] 메시지의 링크를 누르면 등록한 도메인이 열린다.
- [ ] `docs/ops/kakao-check.md`에 다음을 기록한다: 성공 여부, `refresh_token_expires_in`(초), `account_email` 사용 가능 여부, 실패했다면 에러 응답 원문.

## 실패하면

그날 팀에 알린다. 원인이 앱 설정이면 고친 뒤 다시 확인한다. API 자체를 쓸 수 없으면 12/25 알림을 캘린더 추가와 홈 안내 배너(FE-16)로 대신하는 방안을 팀 회의에서 정한다.

## 범위 밖

- 우리 코드로 토큰을 저장하고 보내는 것(BE-04)
