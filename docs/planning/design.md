# Christmas Gift For You 설계

> 문서 체계: `design.md`(구조·핵심 규칙) > `정책명세서.md`(운영 규칙) > `기능명세서.md`(화면·배치) / 일정은 `개발운영계획.md`.
> 기준일: 2026-11-24. `[확정]` = PM 결정 / `[제안]` = 작성 중 정한 기본안.

## 1. 왜 만드나

사람들이 크리스마스에 하고 싶은 것은 **마음을 주고받는 것**이다.

**문제 문장 `[제안]`:** 크리스마스에 마음을 전하고 싶은 사람이, 지인이 멀리 있거나 모이기 어려울 때, 지금은 카톡 선물하기(돈이 들고 메시지가 짧음), 오프라인 마니또(모여야 함), 연말 트리·롤링페이퍼 메시지 서비스(받는 사람 한 명 중심, 그룹 마니또·함께 여는 순간 없음)로 버틴다. 근거는 팀 주변 관찰뿐이다 `[미정]`. 별도 인터뷰는 하지 않는다 `[확정 11/25]`.

**비슷한 서비스와 다른 점 (한 줄):** 트리에 메시지를 거는 형태는 가져오고, **그룹 마니또 + 12/25 12:25 함께 여는 순간**만 다르게 만든다.

**선물**이 중심이다. 음악은 ① 저작권 문제없는 캐롤 배경음, ② 선물상자 안에 넣는 '음반'으로만 쓴다.

**중심 가치 `[확정]`:** 크리스마스에 사람의 마음을 전달하는 것.

## 2. 누구를 위한가

크리스마스에 선물을 주고받고 싶고, 크리스마스를 다같이 즐기고 싶은 사람.

| 사람 | 쓰는 공간 |
|---|---|
| 지인이 별로 없거나, 새로운 사람과의 인연을 원하는 사람 | 공개 트리 |
| 지인끼리 크리스마스를 소소하게 온라인으로 즐기고 싶은 사람 | 비공개 그룹 |

한 사람이 둘 다 써도 된다.

**열린 질문 `[미정]`:** 공개 트리에서 이어지는 수단은 좋아요뿐이다(댓글·DM·팔로우는 비목표). '새 인연'이 제품 안에서 완성되지는 않으므로, 공개 트리의 실제 약속은 "부담 없이 마음을 남기고 반응받는 것"에 가깝다. 타깃 문구를 이쪽으로 좁힐지 PM이 정한다.

## 3. 목표 · 비목표 · 실패 조건

**가설** `[확정 11/24]` (공간마다 하나)
- 공개 트리: 크리스마스에 마음을 남길 곳이 있으면, 지인이 적은 사람도 카드를 걸고 반응(좋아요)을 받는다.
- 비공개 그룹: 지인 그룹은 12/25 12:25에 함께 여는 순간이 있으면, 마감 전까지 멤버 모두가 선물을 보낸다.

**팀 목표** `[확정 11/24]`: 실사용자를 받으며 서비스를 직접 운영·유지보수하는 경험을 얻는다(운영 중 장애 대응 포함, 필요하면 동아리 서버로 이전).

**목표 = 성공 기준** `[확정 11/24]`
- 공개 트리 (분모 = **공개 트리를 한 번이라도 연 가입자**, `[확정 11/24]`): 그중 **80% 이상**이 트리에 카드(편지 포함)를 건다. 그룹에만 들어온 사용자가 이 숫자를 끌어내리지 않도록 분모를 나눴다.
- 비공개 그룹 (분모 = **그룹 멤버**):
  1. 12/24 23:59까지 **그룹 멤버의 80% 이상**이 선물상자를 1번 이상 보낸다.
  2. **멤버 2명 이상인 그룹 중 80% 이상**에서 선물상자를 한 번도 만들지 않은 멤버가 0명이다.
  3. 추첨 후 **멤버 2명 이상인 그룹 중 80% 이상**에서 아무것도 못 받은 멤버가 0명이다 `[확정 11/24]`. 실패 조건 1을 직접 재는 숫자이고, 마니또 추첨이 이 문제를 줄였는지도 이것으로 본다.
- 개봉: 12/25 당일(23:59까지) **그룹 멤버 개봉률**(받은 상자를 1개 이상 연 비율). 목표치는 12/20까지 정한다 `[미정]`.
- 별도 지표(목표 없음): **그룹 참여율** = 가입자 중 그룹 멤버 비율. 공개 트리만 쓰는 사람이 늘어도 그룹 지표가 떨어지지 않도록 분모를 나눴다.
- 판정 시점: 12/24 23:59 마감 기준 (카드는 12/25 23:59 걸기 마감 기준, 못 받은 멤버는 추첨 직후).
- 80%는 근거 없는 목표다 `[확정 11/24]`. 외부 베타가 없어 보정하지 않고 그대로 간다.
- '모두 마니또' 옵션 그룹(§6)이 생기면 그룹 기준 1~3을 **옵션 그룹 / 일반 그룹으로 나눠 함께 보고**한다. 옵션 그룹에서는 기준 2가 구조적으로 충족되고 기준 3도 대부분 충족된다(짝 맞추기가 불가능한 그룹만 예외, §7). 정의는 바꾸지 않는다. **그룹 가설은 일반 그룹으로만 판정**한다 `[확정 11/25]`.
- 기준을 끌어올릴 장치 `[제안]`: 그룹 홈에 숫자는 두지 않되(§6), 12/24 18:00 이후 그 그룹에 상자를 아직 하나도 안 만든 **본인에게만** "아직 보낼 수 있어요" 배너를 띄운다. 운영자는 현황판(A-03)으로 진행률을 본다.

**비목표 (이번 범위 밖)**
- 결제·실물 선물·기프티콘 판매
- 채팅·DM·댓글·팔로우
- 플레이리스트, 노래 검색 API, 앱

**실패 조건 (동작해도 실패로 본다)**
- 그룹 안에 아무것도 못 받은 사람이 생긴다.
- 공개 트리가 광고·괴롭힘 게시판이 된다.
- 비공개 선물 내용이 12/25 12:25 전에 새어 나간다.
- 음악(음반) 기능이 다시 서비스의 중심이 되어 API 제약에 묶인다.

## 4. 구조

```
서비스
├── 배경 캐롤 (모든 화면, CC0·퍼블릭 도메인 음원)
├── 공개 트리 (홈, 1개)
│     └── 카드 (1인 1장) ── 좋아요
└── 비공개 그룹 (여럿, 1인 여러 그룹 가능)
      ├── 멤버 (최대 30)
      └── 선물상자
            ├── 겉: 상자·리본 색, 스티커
            └── 속: 편지 · 사진(최대 5) · 음반(YouTube 링크 1곡, 상자당 1개)
```

### 4.1 두 공간 비교

| | 공개 트리 | 비공개 그룹 |
|---|---|---|
| 들어오는 길 | 홈 (링크 불필요) | 초대 링크 `/g/{code}` |
| 남기는 것 | 카드 = 꾸민 겉모습 + 편지 | 선물상자 = 꾸민 겉모습 + 편지·사진·음반 |
| 받는 사람 | 없음 (트리에 건다) | 지정한 멤버, 또는 마니또(랜덤 1명) |
| 공개 시점 | **거는 즉시** 누구나 읽음 `[확정]` | **12/25 12:25 일괄 개봉** `[확정]` |
| 반응 | 좋아요 `[확정]` | "고마워요" 한 줄 답장 (P2) |
| 사진·음반 | 넣지 않음 `[제안]` | 넣을 수 있음 |
| 수 제한 | 1인 1장 `[제안]` | 지정은 받는 사람당 1개, 랜덤은 1인당 1개 `[제안]` |

## 5. 공개 트리

- 로그인한 사람은 카드 1장을 건다. 카드 = 앞면(기본 카드 이미지 선택 또는 직접 그리기 + 스티커) + 뒷면 편지 + 작성자 프로필 사진 아이콘 `[확정]`. 선물상자 꾸미기를 축소한 형태.
- 받는 사람은 없다. 특정 사람에게 주는 것이 아니라 **트리에 걸어 두는 마음**이고, 인연은 걸린 카드를 보고 좋아요를 누르는 데서 생긴다 `[확정]`.
- 거는 즉시 누구나 내용까지 볼 수 있다. 비로그인도 열람 가능 `[제안]`, 좋아요·카드 걸기는 로그인 필요.
- 좋아요: 한 사람이 **한 카드에 1번**, 대신 **좋아요를 누를 수 있는 카드 수는 제한 없음** `[확정]`. 숫자는 모두에게, 누가 눌렀는지는 카드 작성자에게만 `[제안]`.
- 좋아요 5 이상인 카드는 트리 전체 화면에서 반짝이고, 많을수록 밝다 `[확정: 기준 5]` `[디자인 미확정: 연출]`.
- 댓글 없음 `[제안]`: 모르는 사람끼리의 댓글은 신고 부담이 크다.
- 카드가 많아지면 트리에 다 걸 수 없으므로, 트리에는 장식 칸 수만큼(기본 50) **전부 무작위**로 건다 `[확정]`. 카드를 열면 양옆 화살표로 다음 사람 카드로 넘긴다 `[확정]`. 지인이 적은 사람의 카드도 똑같이 보일 기회를 갖게 하려는 것.
- 12/25 12:25: 공개 트리는 열 것이 없으므로 **트리 불이 켜지는 연출** + "올해 걸린 마음 n개" `[제안]`.
- 내 카드 공유 `[제안]`: [내 카드 공유]로 카드 링크(`/c/{id}`)를 보내면 받은 사람은 그 카드를 바로 연다. 트리 무작위 배치와 따로 움직이므로 "지인 적은 사람도 같은 기회"를 해치지 않는다. 공개 트리 루프의 새 방문자 유입 경로.
- 카드 걸기는 12/25 23:59까지, 좋아요는 12/31 23:59까지, 이후 읽기 전용 `[제안]`.

## 6. 비공개 그룹

- 누구나 그룹을 만들 수 있고 개수 제한은 없다 `[확정]`. **만든 사람과 참여한 사람은 권한 차이가 전혀 없다** `[확정]`. 초대 링크로 들어온 사람은 로그인 후 참여.
- 정원 30명, 참여는 12/24 23:59까지 `[제안]`.
- 멤버는 다른 멤버에게 선물상자를 보낸다.
  - **지정:** 받을 멤버를 고른다. 받는 사람 한 명당 1개.
  - **마니또(랜덤):** 1인 1개. 받는 사람은 마감 후 추첨(§7)으로 정해진다 `[확정: 방식]`.
- 마감 전까지 보낸 상자 수정·취소 가능.
- **'모두 마니또' 옵션** `[확정 11/25]` (필수 기능. 실패 조건 1 '못 받는 멤버'에 직접 대응): 그룹을 만들 때만 켤 수 있고 이후 바꿀 수 없다. 켜면 만든 사람을 포함한 모든 멤버가 **마니또 상자 1개를 만들어야 참여가 끝난다**(벌칙 없음, 참여 조건만). 이 상자는 취소할 수 없고 수정만 된다. 지정 선물은 옵션과 상관없이 그대로 보낸다.
- **그룹 홈** `[디자인 미확정: 프로토타입으로 검토 중]`: 가운데에 메인 구조물(크리스마스 트리, 그 아래 내가 받은 상자 겉모습이 쌓임 `[제안]`)이 있고, **멤버마다 작은 요정이 무작위로 날아다닌다.** 요정을 누르면 "○○님에게 선물상자를 만들까요?" 창 → [만들기]면 받는 사람이 정해진 채로 선물상자 꾸미기로 간다.
  - 받은 수·못 받은 멤버·안 보낸 멤버 같은 숫자는 그룹 홈에 두지 않는다 `[확정]` (이건 기능 결정).
  - 요정에는 그 멤버의 프로필 사진이 작게 붙고, 내 요정은 날지만 눌리지 않는다 `[제안]`. 이미 지정 선물을 보낸 멤버의 요정을 누르면 "이미 보냈어요 · 수정할까요?" `[제안]`.
  - [멤버 보기] 버튼으로 같은 동작을 하는 목록을 둔다. **목록이 최소 기능(P0)이고 요정은 연출(P1)이다** `[확정 11/24]`. 요정을 잡기 어려운 사람(작은 화면, 스크린 리더)도 목록으로 보낸다.
  - **검토 중인 대안: 산타 버전** `[디자인 미확정]`: 멤버 수만큼 넓어지는 하늘 지도에 집 = 멤버. [목록 보기]는 집 위치로 이동만, 집을 직접 눌러야 썰매 이동(0.8초, 탭하면 건너뛰기) 후 집 내부 → [선물 상자 만들기]. 집 트리 아래 상자는 그림으로만 보이고 숫자는 없다. 화면 ID는 `기능명세서.md` ⑦-S. 결정 기한 11/25 (`개발운영계획.md` §11).
- 개봉 전 받는 사람은 **내가 받은 지정 상자의 겉모습(색·스티커)**까지 본다. 보낸 사람과 속(편지·사진·음반)은 잠김. 마니또 상자는 추첨 후 겉모습만 더해진다 `[확정: 겉모습 공개]`.
- 개봉 후: 받은 상자를 하나씩 연다. 지정 선물은 열면 바로 "From. ○○님"이 보이고, **마니또 선물은 열 때 "🎁 마니또는 ○○님이었어요"로 공개** `[확정]`.
- 받은 사람은 상자마다 "고마워요" 한 줄 답장 1회 (P2, 밀리면 자른다).

## 7. 마니또 추첨 `[제안: 알고리즘]`

목표: 그룹 안에 못 받는 사람을 줄인다 (§3 실패 조건).

```
마감(12/24 23:59) 후, 그룹마다:
  받은수 = {멤버: 받은 지정 선물 수}
  마니또들 = 그룹의 마니또 상자들, 그룹 ID로 시드 고정해 섞음
  for 상자 in 마니또들:
      후보 = 멤버 - {보낸 사람}
      후보 = 후보 - {보낸 사람이 이미 지정 선물을 보낸 멤버}   # [확정] 한 사람의 선물이 같은 사람에게 몰리지 않게
      if not 후보: 상자.상태 = 미전달; continue
      최소 = min(받은수[m] for m in 후보)
      받는사람 = 시드 고정 난수로 {m in 후보 | 받은수[m] == 최소} 중 하나
      받은수[받는사람] += 1
      결과 저장
```

- 시드 고정 + 결과 저장 → 다시 돌려도 결과가 같다(멱등).
- 그룹에 보낸 사람 혼자면 미전달. 개봉 때 보낸 사람에게 "받을 멤버가 없어 전달되지 않았어요" 표시.
- 받는 쪽 개수 상한 없음.
- **'모두 마니또' 옵션 그룹** `[제안]`: 위 추첨 대신 **모두 정확히 1개씩 주고받는 짝 맞추기**(자기 자신과 이미 지정 선물을 보낸 상대 제외, 시드 고정). 완전한 짝이 불가능할 때만 위 추첨으로 처리한다.

```
옵션 그룹마다 (마감 후, 기존 추첨과 같은 시점·같은 백업 뒤):
  보낸이들 = 마니또 상자를 낸 멤버 (= 옵션 그룹에서는 전체 멤버)
  if len(보낸이들) < 2: 미전달 처리; 끝
  허용[g] = 보낸이들 - {g} - {g가 지정 선물을 보낸 멤버}
  순서 = 그룹 ID 시드로 보낸이들을 섞은 고정 순서
  배정 = 이분 매칭(보내는 쪽·받는 쪽 = 보낸이들, 간선 = 허용), 순서대로 증가 경로 탐색
  if 모든 보낸이가 짝을 찾음: 결과 저장; 끝
  else: 이 그룹 전체를 위 기존 추첨으로 처리
```

  - 결과는 원 하나가 아니라 여러 원으로 나뉠 수 있다(A↔B, C→D→E→C). 모두 정확히 1개씩 주고받는 점은 같다.
  - 기존 추첨으로 넘어가는 경우는 완전한 짝이 불가능할 때뿐이다. 예: 멤버 2명인데 A가 B에게 지정 선물을 보낸 그룹 → A의 마니또는 미전달.

## 8. 선물상자

| 구성 | 내용 | 위치 |
|---|---|---|
| 상자·리본 색 | 준비된 팔레트 | 겉 |
| 스티커 | 준비된 세트, 눌러서 정해진 자리에 붙이기, 최대 20 `[제안]` | 겉 |
| 편지 | 500자 `[제안]` | 속 |
| 사진 | 최대 5장 (추억 사진·기프티콘 등), jpg/png 장당 5MB | 속 |
| 음반 | 상자당 최대 1개, 표지 색 + 제목 + YouTube 링크 1곡 `[확정]` | 속 |

- 속 구성 중 하나 이상 필수(편지·사진·음반 중).
- 겉면은 색·스티커만. 사진은 열어야 보인다(기프티콘 바코드 노출 방지). 결제 없음.

### 8.1 음반 `[확정: C안]`

- 보내는 사람이 YouTube 링크를 붙여 넣는다. oEmbed로 제목·썸네일 미리보기(API 키·할당량 불필요). **검색 API는 쓰지 않는다.**
- 받는 사람은 개봉 후 음반을 눌러 페이지 안 YouTube 임베드로 재생. 광고는 막지 않는다(약관).
- 음반 재생 중에는 배경 캐롤을 멈춘다 `[확정]`.
- 재생 불가(삭제·퍼가기 금지)면 "지금은 들을 수 없는 노래예요" + 제목 표시.

## 9. 배경 캐롤

- 퍼블릭 도메인 곡(Silent Night, Jingle Bells 등)이라도 **녹음**에는 별도 권리가 있다. CC0·퍼블릭 도메인으로 공개된 녹음, 또는 CC BY(크레딧 표기)만 쓴다. NC·ND 등 조건이 애매한 라이선스는 쓰지 않는다 `[제안]`.
- 5~10곡을 자체 저장소에 두고 순환 재생. 출처·라이선스는 크레딧 페이지에 기록.
- 브라우저 자동재생 제한 때문에 첫 탭(터치) 후 재생 시작. 화면 구석 켜기/끄기 버튼, 선택은 기기에 기억.
