**원칙**
- **백엔드는 FE와 PM이 유동적으로 나눈다** `[확정 11/27]`. 화요일 팀 회의(11/30 주는 월요일)에서 그 주 백엔드 칸을 누가 맡을지 정한다. 11/25~27 백엔드(BE-00~04)는 FE가 진행했다.
- **디자인 일정** `[확정 11/27]`: 11/29(일)까지 전체 화면 초안 → 11/30 팀 회의에서 전원 검수 → 12/2(수) 시안 완성. FE는 그때까지 임시 화면으로 만들고 12/3부터 시안을 입힌다.
- **백엔드: Supabase Cloud 무료 요금제로 먼저 운영한다** `[확정 11/25]`. 내부 QA(12/14~15)에서 사용량과 성능을 재 보고, 무료 요금제로 부족하다는 판단이 서면 12/15 팀 회의에서 **대체 방안**으로 옮긴다.
  - 대체 방안 순서: 동아리 서버(server2)에 Supabase 직접 설치 → server2를 쓸 수 없으면 팀원 개인 미니 PC 서버에 같은 방식으로 설치. 같은 Supabase라 코드는 그대로 쓰고, 로그인 리다이렉트 주소·비밀 키·사용자·사진 데이터·예약 실행만 옮긴다.
  - 판단 기준: 12/10 리허설과 12/14 QA에서 잰 사용량으로 12/21~31 예상치가 무료 한도(파일 저장 1GB, 트래픽 5GB + 캐시 5GB, DB 500MB)의 50%를 넘거나, 응답이 눈에 띄게 느릴 때.
  - 실사용자를 받으며 운영·유지보수하는 경험은 어느 쪽이든 팀이 직접 운영·장애 대응을 맡아 얻는다.
- **사진은 업로드 전 브라우저에서 줄인다** `[확정 11/24]`: 선물 사진 긴 변 1600px JPEG, 프로필 400px + 96px 아이콘, 그린 카드 원본 + 썸네일. 트리에는 썸네일만 불러온다. 무료 요금제의 저장·트래픽 한도를 아끼기 위함.
- **AI와 함께 개발** `[확정 11/25]`: FE·BE는 AI로 코드를 쓰되, 접근 규칙(RLS)·추첨·동시 저장처럼 틀리면 되돌리기 어려운 코드는 반드시 테스트로 검증한다.
- **코드 합치기·배포 확인** `[확정 11/25]`: PM 또는 FE 중 그 주에 여유가 있는 사람이 맡는다. 화요일 팀 회의에서 정한다.
- 접근 규칙이 보안 경계: 개봉 전 선물 잠금, 사진은 보낸·받는 사람만, 그룹 정보는 멤버만, 좋아요 누른 사람 목록은 작성자만.
- 공개 트리는 실시간 구독 없이 진입 시 + 30초 주기 조회 `[제안]`. 몰리면 그때 캐시.
- 배치는 셋: 마니또 추첨(백업 뒤 수동 실행), 개봉 알림(12/25 12:25 예약 실행), 파기(1/31 수동). 마감·개봉·좋아요 마감은 배치 없이 서버 시각 판정.
- 설정값: 마감·개봉 시각, 현재 시각 덮어쓰기.
- FE는 API를 기다리지 않고 가짜 데이터로 시작하고, 시안이 나오기 전까지 임시 화면으로 만든다. 결정은 해당 명세에 바로 반영.
- **디자인은 전원이 검수한다** `[확정 11/24]`. 방향(요정/산타 등)만 11/25에 정하고, 세부 디자인은 구현 기간 동안 디자이너와 상의하며 확립한다.

| P2 | 트리 점등 연출, 고마워요 답장, 보낸 상자 화면, 스티커 끌기·크기 |
| 제외 | 댓글·DM, 플레이리스트, 노래 검색 API, 결제, 탈퇴, 앱 |

**밀릴 때 자르는 순서:** P2 전부 → ④ 카드 목록·직접 그리기 → 요정(산타) 연출(멤버 목록으로 대체) → 스티커(색만) → 음반 → 사진.

**자르지 않는 것:** 편지, 마니또, 모두 마니또 옵션, 12/25 개봉, 카톡 알림, 신고 기능, 접근 규칙, 지표 이벤트.

**성공 기준 (`design.md` §3):** 공개 트리를 연 가입자 80% 카드 걸기 / **그룹 멤버** 80% 선물 1번 이상 보내기 / 멤버 2명 이상 그룹 중 80%에서 선물 안 만든 멤버 0명 / 추첨 후 **못 받은 멤버가 없는 그룹 80%**(멤버 2명 이상) / 12/25 당일 개봉률. 80%는 근거 없는 목표로 두고 보정하지 않는다.

**지표 이벤트:** 가입, **공개 트리 열기(가입자별 첫 1회)**, **비로그인 트리 열기 → 가입 → 카드 걸기 흐름**, 카드 걸기, 그룹별 선물 안 만든 멤버 수, 좋아요, 그룹 생성, 초대 링크 열기 → 참여, 선물 보내기(방식별), 그룹당 멤버·선물 수, **추첨 후 못 받은 멤버 수**, **그룹 참여율(가입자 중 그룹 멤버 비율)**, 12/25 당일 개봉률, 음반 재생, 배경 캐롤 끔 비율. **모두 마니또 옵션(사후 분석·발표용):** 옵션 그룹 생성 수, 초대 → 참여 전환율(옵션/일반), 참여 모드 꾸미기 완료율, 짝 맞추기 불가 그룹 수. 그룹 성공 기준 1~3은 옵션/일반으로 나눠 보고하고, **그룹 가설은 일반 그룹으로만 판정**한다.

## 4. 1주차 (11/25 ~ 11/29): 위험 확인 + 공개 트리 완주

**완료 기준:**
1. **카카오 알림 실발송(관문 1):** 동의 화면 → 저장된 토큰으로 테스트 계정에 카톡 1통 수신, 하루 발송 한도 확인 (BE-00에서 확인).
2. **개봉 전 잠금 테스트 1개 통과:** 받는 사람·그룹 밖 계정이 개봉 전 선물 내용을 직접 조회할 수 없다 (BE-02).
3. **공개 트리:** 카톡 인앱에서 홈을 열면 외부 브라우저로 넘어가 로그인 → 카드 걸기 → 트리에 보임. 좋아요·신고·관리자 숨김은 API와 DB로 확인한다(카드 보기 화면은 11/30). 비로그인으로 좋아요 누른 사람 목록을 DB에서 직접 읽을 수 없다.

**11/25 (수) 오전 결정 회의 안건**
1. **기본안 일괄 확정:** 공개 카드 사진·음반 제외·1인 1장·댓글 없음, 그룹 정원 30·나가기·강퇴 없음. **11/25 정오까지 이견이 없으면 기본안대로 확정**한다.
2. **그룹 홈 디자인 방향(요정 / 산타)**: PM이 디자이너와 논의해 11/25까지 정하고 전원이 검수한다. 어느 쪽이든 멤버 목록이 P0, 연출은 P1.
3. **의견 취합: 첫 유입 채널과 그룹 개설자 10명.** 현재 구상은 **인스타그램 홍보**, 그룹 개설자 10명은 **팀원 지인 중에서 선정**하는 방식. 추가 의견을 모아 확정한다.
4. 카카오 알림 스파이크 담당과 결과 공유 시각.
5. 성공 지표 수정 공유 (`design.md` §3).
6. **모두 마니또 옵션 공유**: 필수 기능으로 확정, 다른 기능은 빼지 않고 버퍼로 감당한다. 이유: 실패 조건 1(못 받는 멤버)에 직접 대응.
7. **백엔드 공유**: Supabase Cloud 무료로 운영 시작, 12/15에 유지/대체(server2 → 미니 PC) 결정.

회의에서 못 정한 항목은 그 자리에서 새 기한을 정해 §11에 적는다. 갱신이 밀린 산출물(`images/` 흐름도 등)도 함께 기록한다.
