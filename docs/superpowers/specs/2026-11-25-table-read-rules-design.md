# 클라이언트가 직접 읽는 테이블 정리 · 설계 (작은 변경)

작성일 2026-11-25 · 상태: 승인됨

## 의도

FE 개발자가 구현하면서 "이 테이블을 내가 조회하면 무엇이 오는가"를 한곳에서 찾게 한다. 아직 FE 작업 전이라 막힌 곳은 없고, 막히기 전에 빈 곳을 채운다.

Supabase는 REST 엔드포인트(URL, HTTP 메서드)를 자동으로 만들고, 컬럼 타입은 `supabase gen types`가 준다. 자동으로 나오지 않는 것은 RLS 때문에 누구에게 어떤 행이 보이는지, 언제부터 보이는지다. RPC 시그니처, 에러 코드, `GiftBoxInput`은 이미 BE 명세와 README에 있다. 읽기 규칙은 BE-01·02·03·07·10·11과 기술 문서 4.2절에 문장으로 흩어져 있다.

## 목표 / 범위 밖

- 목표: `backend/spec/README.md`에 「클라이언트가 직접 읽는 테이블」 표를 추가한다. 테이블·버킷마다 누가 읽나, 시각 조건, 직접 쓰기 가능 여부, 대표 조회 예시, 근거 명세를 적는다.
- 범위 밖: 새 규칙 만들기, 컬럼 타입 나열(`gen types`가 맡는다), RPC·Edge Function 재정리(이미 각 명세에 있다).
- 실패 조건: 기존 명세와 다른 내용을 적는 것. 명세끼리 다른 곳은 고치지 않고 표시만 한다.

## 검토한 방식

| 안 | 내용 | 결과 |
|---|---|---|
| 큰 `docs/api.md` | 모든 RPC·테이블·에러를 한 파일로 모으고 BE 명세는 링크로 바꾼다 | 기각: 이미 있는 내용이 대부분이라 옮기는 비용만 크다 |
| 명세마다 나눠 적기 | BE-02·03·06·07 인터페이스 절에 각각 추가 | 기각: 지금처럼 흩어진 상태가 유지된다 |
| **README에 표 하나 추가** | FE가 이미 보는 에러 코드 표 옆에 둔다 | **채택** |

## 결정

- 위치: `backend/spec/README.md`, 「에러 코드」 절 바로 뒤.
- 조회 예시는 `supabase-js` 문법으로 쓴다.
- RLS로 막힌 읽기는 에러가 아니라 0행이라는 점을 함께 적는다.
